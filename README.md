# Fitcheck

A local, weather-aware digital wardrobe. Upload the clothes you actually own,
then roll a complete look that matches today's forecast. Save the good ones,
swap individual pieces, and curate everything from one small web app.

No accounts, no cloud, no API keys. Your data stays in this folder.

## Run it

```bash
./run.sh
```

Open **http://127.0.0.1:8000**.

The first run creates `.venv-app/` and installs the pinned dependencies from
`pyproject.toml` / `uv.lock`. Keeping this environment separate means an
existing `.venv/` in the folder is left untouched.

Useful variants:

```bash
./run.sh --reload          # auto-reload while editing
PORT=9000 ./run.sh         # another port
```

If you prefer doing it by hand:

```bash
UV_PROJECT_ENVIRONMENT=.venv-app uv sync
UV_PROJECT_ENVIRONMENT=.venv-app uv run uvicorn app.main:app --reload --port 8000
```

## What's inside

- **Today's look** (`/`) — three 3:4 cards for Top, Bottom, and Shoes.
  - Arrows cycle within each category without a server round trip.
  - **Generate** asks the API for a weather-appropriate combination, with a
    short shuffle animation.
  - The **heart** saves the exact combination. Already-saved combinations show
    a filled heart, and liking twice never creates a duplicate.
  - Off-forecast pieces get an amber dot and the fallback is called out below
    the cards.
- **Wardrobe** (`/wardrobe`) — drag-and-drop upload with description,
  cold/hot/both tag, and type. Three horizontal rails (Tops, Bottoms, Shoes)
  with arrow scrolling. Click a thumbnail for the item modal.
  - Prefer Finder? Drop photos straight into
    `uploads/<type>/<weather>/` and press **Scan folders** (the page also scans
    on load). The filename becomes the description.
  - Deleting an unused item asks for a normal confirmation.
  - Deleting a used item offers **replace it** with another same-type piece
    (saved outfits are updated in place) or **delete the outfits too**. Cancel
    changes nothing.
- **Outfits** (`/outfits`) — every saved look, newest first, grouped by day.
  Weather is a snapshot from when the look was saved, and a hint appears when
  today differs. Remove any look with the × button.

Every page loads the current weather and updates the chip in the top-right.
Click the chip to refresh.

## Data and files

| Path | What it is |
|---|---|
| `wardrobe.db` | SQLite database (items, outfits, weather cache) |
| `uploads/<type>/hot/` | Images for hot weather |
| `uploads/<type>/cold/` | Images for cold weather |
| `uploads/<type>/both/` | Images that work in either weather |
| `.venv-app/` | App environment created by `uv` |

`<type>` is `top`, `bottom`, or `shoes`. Each folder keeps the original plus a
`<name>_thumb.jpg` generated by the app. Drop images into these folders through
Finder (or the Wardrobe upload form), then press **Scan folders** or reload the
page. A filename like `cream_cable-knit.jpg` becomes the description
“cream cable knit”; the folder decides the weather tag.

The database stores image paths relative to `uploads/`, never the image bytes.
To start over, stop the server and delete `wardrobe.db` plus the contents of
`uploads/`; both are recreated on the next start.

## Catalog-style photos

Thumbnails are rendered like a digital wardrobe, not like camera-roll photos:
Apple Vision cuts the garment out of the background, then it is placed on a
soft blush gradient with a subtle shadow. This happens automatically for new
uploads on macOS 14+ (the Xcode Command Line Tools provide `swiftc`).

To re-render the whole closet — for example after changing the background or
after adding photos in Finder — run:

```bash
.venv-app/bin/python tools/digitize_thumbs.py
```

Pass specific files or folders to limit the run. Originals are never modified;
only `<name>_thumb.jpg` is replaced. On a machine without Vision, uploads fall
back to plain photo thumbnails and everything else keeps working.

## Weather

- Browser geolocation is used only when permission is **already granted** — the
  app never prompts on first load.
- Server fallback: `https://ipapi.co/json/` for approximate coordinates.
- Forecast: [Open-Meteo](https://open-meteo.com/) (free, no key).
- Final fallback: `51.5072, -0.1276` (London), clearly marked in the UI.
- Apparent temperature ≥ **18 °C** → `hot`; below → `cold`.
- A reading is cached per local day for **30 minutes**. If the network is down,
  the last reading is served with `stale: true`. If there is no reading at all,
  the UI shows a banner with a manual Cold/Hot override so the app still works.

Environment overrides (all optional):

```bash
WARDROBE_HOT_THRESHOLD=20       # °C boundary between cold and hot
WARDROBE_WEATHER_TTL_MINUTES=30
WARDROBE_DEFAULT_LAT=40.7128
WARDROBE_DEFAULT_LON=-74.0060
WARDROBE_DEFAULT_LOCATION="New York"
WARDROBE_DB=/path/to/wardrobe.db
WARDROBE_UPLOAD_DIR=/path/to/uploads
```

## API

Interactive docs: **http://127.0.0.1:8000/docs**

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/health` | Liveness check |
| GET | `/api/weather?lat=&lon=` | Today's reading (cached) |
| GET | `/api/items?type=&weather=` | List/filter pieces (`both` matches either) |
| POST | `/api/items/sync` | Scan the upload folders for new images |
| POST | `/api/items` | Multipart upload (`file`, `description`, `weather`, `type`) |
| GET | `/api/items/{id}` | One piece |
| GET | `/api/items/{id}/outfits` | Outfits that reference it |
| POST | `/api/items/{id}/replace` | Swap it in saved outfits (`replacementId`) |
| DELETE | `/api/items/{id}?force=true` | Delete; used items return `409` first |
| POST | `/api/generate` | Weather-aware random look |
| GET | `/api/outfits` | Saved looks with joined items |
| POST | `/api/outfits` | Save a look (idempotent) |
| DELETE | `/api/outfits/{id}` | Remove a saved look |

Uploads accept JPG, PNG, WEBP, and GIF up to 10 MB. HEIC/HEIF gets a specific
error explaining how to convert it. `weather` is `cold`, `hot`, or `both`;
`both` pieces are eligible in either forecast.

## Project layout

```
app/
  main.py        FastAPI app, mounts, pages, startup
  config.py      paths and tunables
  db.py          schema, connections, query helpers
  models.py      request/response models
  weather.py     Open-Meteo, IP fallback, cache, cold/hot mapping
  images.py      validation, storage, thumbnails, safe deletion
  importer.py    scans uploads/<type>/<weather>/ for dropped images
  routes/        items, outfits, generate, weather
static/
  css/styles.css
  js/            api, ui, main, wardrobe, outfits
templates/       index, wardrobe, outfits
uploads/         runtime images in hot/cold/both folders (gitignored)
tools/           Vision cutout helper + catalog thumbnail script
wardrobe.db      runtime database (gitignored)
```

## Notes

- Python 3.9+ compatible source; dependencies are installed with `uv`.
- The server binds `127.0.0.1` only. This is a single-user local app and has no
  authentication — do not expose it publicly without adding auth.
- Image files are served statically from `/uploads`; originals and 600 px
  thumbnails are kept side by side.
